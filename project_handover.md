## 1. Core Architecture

The page functions as a single-page application with two distinct states: **Hero** and **Details**.

- **State Management**: Controlled via `body.show-details` and `body.off-hours`.
- **Navigation**: Implicit (scroll) and Explicit (sidebar dots).
- **Layout Engine**: Custom CSS Grid + Flexbox.

## 2. The "Details" Panel Logic

The details panel is the heart of the interaction complexity. It slides up over the fixed Hero section.

### Positioning Strategy (Updated)

- **Panel**: `position: fixed`. It transitions its `top` property.
  - **Open**: `top: 0` (COVERS FULL SCREEN).
  - **Closed**: `top: 100vh`.
  - **Height**: `100vh`.
- **Scrolling**: The panel itself has `overflow: hidden`. It **DOES NOT** scroll. The global window scroll is disabled.

### Independent Scrolling (Middle Column)

- The middle column (`.experience-column`) is the only scrollable area.
- **Height**: `100vh`.
- **Overflow**: `overflow-y: auto`.
- **Top Padding**: `calc(var(--sticky-height) + var(--details-top-padding))` to push content below the translucent header.
- **Scrollbar**: Hidden (`display: none` / `scrollbar-width: none`).

### Global Scroll Forwarding (The "Gotcha")

Since the main panel doesn't scroll, scrolling over "dead zones" (margins/gaps) would normally do nothing.
**Solution**: A global `wheel` event listener on `document`.

1.  **Capture**: Detects scroll events anywhere on the page.
2.  **Forwarding**: If not hovering a scrollable side column, explicitly update `.experience-column.scrollTop`.
3.  **Exceptions**: Hovering Side Columns allows their _internal_ native scroll, UNLESS they are at the top and scrolling UP (see below).

## 3. Elastic "Pull-to-Close" Transition

This is the signature interaction. Pulling down on the feed (scrolling UP at the top) creates a rubber-band effect before snapping back to the Hero.

### Logic Flow

1.  **Detection**: `wheel` event checks if `experience-column` is at `scrollTop <= 0`.
2.  **Resistance**: Applies `transform: translateY(offset)` to the ENTIRE `.details-panel`.
    - _Crucial_: Sticky/Fixed columns move _with_ the panel because they are children.
3.  **Thresholds**:
    - `WHEEL_THRESHOLD`: **130** (Amount of raw delta needed).
    - `ELASTIC_MAX`: **70px** (Max visual stretch).
4.  **Transition Trigger**:
    - When threshold met -> calls `goToPanel('hero')`.
    - **CRITICAL FIX**: Do **NOT** reset the elastic transform immediately. Keep the panel "stretched" while it starts sliding down to `100vh`. Reset it only after the 0.8s transition completes. This prevents the "upward jump" glitch.
